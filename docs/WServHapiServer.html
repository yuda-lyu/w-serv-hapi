WServHapiServer

WServHapiServer

new WServHapiServer(optopt) → {Object}

Description:

  • Hapi伺服器端之資料控制與同步器

    身分驗證責任(跨套件原則,見自有套件庫主控之 dspec「使用者身分驗證原則」): 本套件不驗證token, 只於各關卡呼叫使用方注入之函數; 未注入時之預設為放行或無身分(verifyConn未給即全部放行、getUserIdByToken預設回空字串). 使用方須自行完整驗證——verifyConn驗連線之token(含本系統使用者存在、啟用、部署方授權); getUserIdByToken反查執行身分, 即驗證身分, 須同等完整, 不可只解碼或只查id; authorizeExec授權表操作(預設拒絕); apis路由不經verifyConn、與kpFunExt皆須各自把關, 含函數層級之角色或成員檢查. 系統函數([sys:getFuncList]、[sys:getTableTags]、[sys:polling])之身分關卡由opt.sysFuncsPublic決定(原樣轉傳w-serv-webdata): 預設三者皆公開以相容既有前端元件, 使用方應於前端改用帶token之元件(WServHapiClient之getToken, 輪詢亦帶之)後顯式設為只公開['[sys:getFuncList]'], 使無有效身分者取不到同步表時間戳與廣播; 未登入須能進登入頁者須列出確實需要者. 輪詢之身分經getUserIdByToken每輪反查(已發布之舊前端元件之輪詢未帶token, 以無身分處理而不反查)並與clientId綁定, 同一前端連線中途換成他人身分(含無身分與有身分互換)會被拒絕, 換身分請重新載入頁面或重建前端連線.

輸入呼叫API時之連線檢測函數，原樣轉傳w-converhp，可使用sync或async函數，回傳嚴格等於true才放行。作用於本套件之通訊路由(含切片上傳與下載)，不作用於靜態檔案與apis。未給(undefined或null)時全部放行；有給但非函數時不拋錯，通訊路由一律以permission denied拒絕，並由w-converhp於建構期間發出一則error事件。切片上傳另須於getInstWConverServer所得實體註冊upload監聽才會受理(本套件與w-serv-webdata皆不註冊)，未註冊時於寫入pathUploadTemp之前即回應'no listener for event[upload]'並發出error事件；註冊後若未給verifyConn，匿名請求亦可呼叫切片上傳而寫入pathUploadTemp。表操作之授權另由authorizeExec負責，預設()=>{return true}
getUserIdByToken function <optional>
 async()=>''

輸入取得使用者ID的回調函數，原樣轉傳w-serv-webdata，傳入參數為前端提供之token字串(前端opt.getToken之值)，可使用sync或async函數，回傳非字串時視為空字串。此即驗證身分之步驟，須完整驗證(token有效、本系統使用者存在且啟用、部署方授權)，不可只解碼或只查id，與verifyConn所驗證者同等完整；其token取自請求內容(固定鍵__sysToken__)，與verifyConn所驗證者為不同來源，兩個身分各自須經完整驗證。系統函數與輪詢亦經此反查(帶token鍵之輪詢每輪反查一次；已發布之舊前端元件之輪詢未帶token鍵，以無身分處理而不反查)，預設回空字串即無身分，是否放行見sysFuncsPublic。拋錯或reject時一律拒絕該次呼叫(含列於sysFuncsPublic者)：一般呼叫其值原樣成為回應訊息並發出error事件；輪詢則前端只見固定訊息'[sys:polling] permission denied'，伺服端error事件為{ msg: '[sys:polling] verifyPolling error', err: 其值 }；有給但非函數時建構即同步拋錯，預設async()=>''
sysFuncsPublic Array <optional>
 ['[sys:getFuncList]','[sys:polling]','[sys:getTableTags]']

輸入無須身分即可呼叫之系統函數名陣列，原樣轉傳w-serv-webdata(1.1.16起)，元素須為'[sys:getFuncList]'(函數名稱清單)、'[sys:getTableTags]'(同步表名與時間戳)、'[sys:polling]'(輪詢，取走該前端之廣播，含同步表時間戳廣播與部署方broadcast之內容)之一。列於其中者getUserIdByToken得空字串亦放行，未列者須得非空字串，否則拒絕：呼叫回應permission denied，輪詢則前端只見固定訊息'[sys:polling] permission denied'，原因經error事件供稽核。預設三者皆公開(相容既有行為：已發布之前端元件輪詢不帶token，預設收緊會使其即時同步失效)；框架預設為放行，使用方須自行設定——建議使用端於前端改用帶token之元件後，顯式設為只公開['[sys:getFuncList]']，使無有效身分者取不到同步表時間戳與廣播；空陣列則連函數名稱清單亦須身分。getUserIdByToken固定回空字串或沿用預設之部署(例如未登入須能進登入頁之單一登入系統)於嚴格設定下須列出前端未登入時要呼叫者(通常為三者)，否則前端因輪詢被拒絕而永不綁定。輪詢之身分與clientId綁定(以userId而非token計，同一使用者換另一枚token不受影響)：同一前端連線(同一clientId)中途改以他人身分輪詢會被拒絕，含無身分與有身分互換(預設三者皆公開時匿名亦被綁定，故由無身分變有身分亦被拒絕)，error事件原因為'clientId belongs to another userId'；嚴格設定下由有身分變無身分者則先被關卡拒絕(原因'empty userId')，不待歸屬解除且之後仍被拒絕。被拒絕之輪詢不刷新在線身分，至舊綁定因該clientId逾時離線(w-serv-broadcast之在線逾時約10秒)解除為止，期間之表變更推播不補送，故換身分(例如登出再以他人登入)請重新載入頁面或重建前端連線(新clientId)，不可只改getToken之回傳值。與useDbOrm無關；未給(undefined或null)時取預設；有給但非陣列或元素非上述三者之一時建構即同步拋錯(例如invalid opt.sysFuncsPublic)，建構後修改原陣列不生效，預設['[sys:getFuncList]','[sys:polling]','[sys:getTableTags]']
useDbOrm Boolean <optional>
 false

輸入是否開啟資料通道，原樣轉傳w-serv-webdata。給予true代表前端可直接呼叫由tableNamesExec與methodsExec組成之表操作(例如'tabA.select')，並自動同步tableNamesSync所指定之資料表至前端，此時operOrm、tableNamesExec、authorizeExec為必填，未給或無效時建構即同步拋錯。未指定(非布林值)時視為false，此時若給了operOrm、tableNamesExec、methodsExec、authorizeExec、kpOrm或tableNamesSync，建構即同步拋錯，預設false
kpOrm Object <optional>
 null

輸入各資料表的操作物件，原樣轉傳w-serv-webdata，用以提供由tableNamesSync指定資料表的change事件，key為表名而值為該表的操作器實體(可使用例如WOrmMongodb等建立)。useDbOrm=true時必填且須為物件，否則建構即同步拋錯；為空物件時不同步；tableNamesSync之各表須在其中且可監聽change事件，否則建構時同步拋錯，預設null
operOrm function <optional>
 null

輸入各資料表的操作通用接口函數，原樣轉傳w-serv-webdata，傳入參數依序為userId、tableName、methodName、input，用以執行tableNamesExec所指定資料表之例如'select'、'insert'、'save'、'del'。前端呼叫表操作時須先通過authorizeExec授權才會呼叫operOrm，operOrm不負責授權。useDbOrm=true時必填，預設null
authorizeExec function <optional>
 null

輸入資料表操作之授權函數，原樣轉傳w-serv-webdata，useDbOrm=true時必填。前端呼叫表操作時，於呼叫operOrm之前傳入物件{ userId, tableName, methodName, input }，可使用sync或async函數。採預設拒絕，回傳值須嚴格等於true才放行，其他值一律拒絕並回應'permission denied'且不呼叫operOrm；拋錯或reject時其值原樣成為回應訊息。userId取不到時為空字串，宜拒絕；methodName宜以白名單判斷。不作用於kpFunExt與系統函數，其拒絕亦不發出error事件。同步資料時前端以不帶參數之表操作select取整表，故tableNamesSync內之表其select須對所有連線者放行，否則被拒絕之前端取不到該表資料(既有資料維持不變)，且每次重抓皆於前端發出error事件，預設null
tableNamesExec Array <optional>
 null

輸入指定能被操作的表名陣列，原樣轉傳w-serv-webdata，各元素須為非空字串，useDbOrm=true時必填(可為空陣列)，否則建構即同步拋錯，預設null
methodsExec Array <optional>
 ['select','insert','save','del']

輸入指定綁定操作器的方式陣列，原樣轉傳w-serv-webdata，各元素須為非空字串，可選'select'、'insert'、'save'、'del'、'delAll'。未給時取預設['select', 'insert', 'save', 'del']；useDbOrm=true時若有給須為陣列，否則建構即同步拋錯
tableNamesSync Array <optional>
 null

輸入指定能被同步的表名陣列，原樣轉傳w-serv-webdata，各元素須為非空字串。各表須在kpOrm中且可監聽change事件；前端以表操作select取同步資料，故各表亦須在tableNamesExec中且methodsExec含'select'(kpFunExt提供之同名函數不算)，違反者建構即同步拋錯；未給時不同步，預設null
kpFunExt Object <optional>
 null

輸入額外擴充執行函數物件，原樣轉傳w-serv-webdata，須為純物件，key為函數名而值為函數(值非函數時建構即同步拋錯)，函數第1參數為userId(取不到時為空字串)，之後為前端給予之參數。不經authorizeExec須各自把關。函數名須能被前端綁定：路徑不得為空或有空段，各段不得為'proto'、'constructor'、'prototype'，不得以'[sys:'開頭，頂層名不得為表名(例如表名為'tabA'時，'tabA'、'tabA.count'、'tabA[select]'皆不可)，且不同函數名不得解析為同一路徑或互為前綴(例如'a'與'a.b')，違反者建構時同步拋錯，預設null

 './tableTags.json'

輸入儲存各資料表時間戳檔案路徑串，轉傳w-serv-webdata，有給但非非空字串時建構即同步拋錯；未給時相容舊名fnTableTags，預設'./tableTags.json'

 ()=>'{random string}'

回傳事件物件，可監聽error事件，涵蓋啟動失敗與執行期錯誤(含w-converhp、w-serv-webdata、w-serv-broadcast、w-sync-webdata經本套件轉送者)，內容依來源層而異(hapi之Error、w-converhp之訊息字串、w-serv-broadcast與w-sync-webdata之{msg,err})；建構期間發生者於建構子回傳後才發出，故須於new之後立即監聽；未監聽error時改以console.error輸出(前綴[w-serv-hapi])，預設只輸出固定標籤與錯誤類別、代碼之安全摘要，不含錯誤訊息文字與資料值，細節由opt.logDetail或opt.funLog取得(見opt.funLog)；error監聽器之同步拋錯不會使行程崩潰(改以console.error輸出)，亦不影響ready與stop之結果。設定錯誤(例如useDbOrm=true而未給authorizeExec、useInert有給但非布林值)於建構時同步拋出(w-serv-webdata之設定錯誤拋出時，pathUploadTemp資料夾可能已由w-converhp建立)。另提供：ready函數，回傳promise，伺服器啟動成功時resolve為hapi伺服器實體，啟動失敗(例如埠被占用、apis路由衝突)時以原錯誤reject；stop函數，回傳promise，等待啟動結束後依序釋放下游於同一事件物件上所建立之資源(w-serv-broadcast之輪詢計時器與在線偵測；資料同步：移除掛於kpOrm之change監聽、取消待推播之時間戳並將尚未落檔者寫入檔案，落檔失敗時發出error事件)再停止伺服器，恆resolve，失敗時發出error事件。停止時不再接受新連線，閒置之連線立即關閉，仍有請求進行中之連線最多等待5秒(hapi之預設)後中斷；stop只等連線，不等也不中止應用端之處理(operOrm、kpFunExt等)與上傳之合併worker：連線已中斷者(例如前端已停止而中止其請求)stop即完成，其處理仍續行並照常寫入副作用，Node行程待其完成才結束；前端未中止之請求(例如使用端之$fapi呼叫)於連線被中斷時失敗並依其重試設定重試，故宜先停止前端再停止伺服器。停止為終態：其後ready仍回傳原結果，再呼叫stop回傳同一promise而不再停止，請勿以getServer所得實體重新start(下游已釋放，只剩半個服務)。停止時w-serv-broadcast對已進入之前端補發之clientLeave與clientChange於其後約1ms才送達，可能晚於stop之promise；前端停止而伺服器繼續服務時，w-serv-broadcast約10秒(其在線逾時)後才判定該前端離線並發出clientLeave。同一行程內多個實例須給不同之fpTableTags與pathUploadTemp。本套件不註冊process之unhandledRejection、uncaughtException與uncaughtExceptionMonitor監聽，全域錯誤政策由使用端自行決定；getServer函數，回傳promise，resolve為hapi伺服器實體(不保證已啟動，確認啟動請用ready)，其stop、start請勿自行呼叫(並發時本物件之stop會於hapi停止前即resolve)，停止請一律用本物件之stop；getInstWConverServer函數，回傳promise，resolve為經w-serv-webdata擴充後之通訊實體，可於其上註冊upload監聽以受理切片上傳；其上另有w-converhp所掛之stop，呼叫會直接停止本伺服器而不釋放下游資源，停止請一律用本物件之stop
